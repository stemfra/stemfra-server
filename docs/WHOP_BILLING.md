# Whop subscription integration

## Ownership and customer journey

Whop collects managed website USD299/month and AI Starter/Growth/Business USD100/200/300 monthly subscriptions. Airwallex remains for custom software. Existing Stemfra invoice history, numbering/PDF presentation and editable billing addresses remain. Public Subscribe routes through Stemfra signup/login and Billing so an authenticated owner selects the website/workspace before checkout. Generic plan links alone cannot grant access.

1. An authenticated owner requests checkout. Server chooses the approved plan and records a private checkout intent with site/workspace ID, owner, verified account email, environment and plan. Pending checkouts are resumed; another checkout is refused while a subscription has a paid future period.
2. The server creates a Whop checkout configuration with the intent UUID in metadata and a stable idempotency key, then persists the checkout ID and URL. The browser redirects to Whop, where the customer supplies payment/billing details and email. The return URL never activates access.
3. A signed webhook is verified from its untouched raw body using the official Whop SDK. The server retrieves current payment/membership data and verifies account, environment, plan, USD amount, monthly interval and ownership binding. Failed/refunded payments never activate a new subscription.
4. A database transaction deduplicates deliveries and payment IDs, synchronizes the subscription and creates one paid Stemfra charge per successful payment. Tax is preserved separately. Older deliveries cannot regress the current paid period. AI grants monthly plan credits once per renewed period, replacing unused plan credits while preserving top-up credits.
5. Paid invoices appear in Stemfra history with a PDF and Whop payment reference. A durable outbox queues a Stemfra receipt to the email captured from the authenticated Stemfra owner. The Whop checkout customer email is retained for reference; it is not used to decide tenant ownership. Receipt emails require the separate delivery flag and Resend configuration.
6. Whop manages recurring collection and subscription/payment-method changes. Billing links to the verified provider management URL. Payment failures do not create Airwallex payment requests. Local manual plan/cancel/payment confirmation paths cannot edit Whop subscriptions. CMS publishing requires a current paid Whop subscription when the release flag is enabled. AI credit spending refuses an expired Whop period.
